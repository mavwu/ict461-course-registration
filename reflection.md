# ICT461 Course Registration — Reflection

This interface was designed as a focused course-registration journey rather than a generic form. The visual direction uses a dark forest green, lime accent and generous spacing to make the page feel calm, purposeful and easy to scan. The hero area answers the main questions immediately: what the course is, whether registration is open and what the student should do next. The course snapshot and overview then provide supporting information before the form asks for any personal details.

Semantic HTML was important to the structure. I used a header, navigation, main content, sections, an aside, a footer, fieldsets and legends so the page has meaningful landmarks and grouped form controls. Every input has a visible label, and the required fields are identified in both text and the form instructions. Native input types, select elements, a checkbox and a real submit button keep the controls keyboard friendly. Focus-visible styles make keyboard movement clear, while the layout remains readable at smaller widths through a responsive grid and a mobile breakpoint.

The JavaScript interaction is the registration validation flow. It checks the name, student number, email, study mode, class time and prerequisite confirmation. Each error is placed next to its related control, `aria-invalid` communicates the state, and the live status region gives a clear summary. A valid submission displays a confirmation message without pretending to send data to a server. This keeps the prototype honest while still demonstrating the complete interaction.

DevTools helped verify the implementation. The Elements view confirmed the semantic structure and accessible attributes, while the Network view showed that the page loads its HTML, CSS and JavaScript as separate resources. One lesson was that a polished interface still needs restrained motion, strong focus states and useful error copy; visual hierarchy alone is not enough. If this became a production form, I would connect the submission to a secure backend and test it with a screen reader and real student feedback.
